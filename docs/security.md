# 安全边界

## 分类与 MCP 是只读路径

`imap_source.py` 使用 LOGIN、EXAMINE、UID SEARCH 与 BODY.PEEK 获取邮件；不会通过这条路径设置已读、移动或删除邮件。MCP 仅暴露 `list_categories`、`classify_jsonl`、`classify_imap`。

包内另有显式 CLI `apply` 写通道。不能把“整个 Python 包无写操作”当成保证；模型通过本 MCP server 则没有写工具可调用。

## 模型与数据

- 邮件主题、发件人和正文是不可信数据，放入带 nonce 的数据信封，不作为工具授权。
- 提示词隔离只能缓解注入；模型仍可能被误导，结构正确也不代表语义正确。
- 输出只接受类别白名单中的 `category` 与简短 `reason`，不从非法输出里猜分类。
- 内容会发送至配置的模型 API；部署者须确认端点可信、传输通道和留存政策。
- 字节/调用/时间预算控制模型调用，但不是全邮箱流量隔离：IMAP 会先获取 MIME 内容再提取、截断文本。

## 凭据与日志

- 凭据从环境变量、严格权限文件或 macOS 钥匙串读取，不要求写入代码或分类配置。
- 配置拒绝常见密钥字段；这不等于任意输入文本都会被识别为敏感信息。
- 分类日志会尽力掩码地址、截断主题与理由，但不是完整 DLP，不能保证清除所有敏感内容。模型理由可能复述邮件中的敏感内容。
- `apply.jsonl` 保存目标目录与主题，按敏感本地数据管理。
- `.gitignore` 排除运行结果、个人配置和常见密钥文件；不要用 `git add -f` 上传这些内容。

## MCP host 的信任边界

`classify_jsonl` 能读取 server 进程可访问的本地文件路径。仅把 server 接给可信 host，不当作多租户沙箱或公开网络服务。不要给 host 不必要的文件访问权限。

## 可选目录写入

`apply` 默认预演，需要操作者显式加 `--apply`。copy 会新增副本；move 需要服务器支持 UID MOVE，并会从源目录移走邮件，历史真实邮箱试验未验证 move。该操作没有去重或事务回滚，部分失败后必须先核对服务器，再决定后续操作。模型分类、预演成功、IMAP 返回 OK 都不能代替实际状态核对。

本项目没有发送、回复、转发或显式 EXPUNGE 工具；UID MOVE 本身会从源目录移走邮件，不能称作“邮箱状态不变”。
