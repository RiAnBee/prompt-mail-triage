# 运维与 Thunderbird

## 环境变量

| 变量 | 默认 / 含义 |
|---|---|
| `EMAIL_TRIAGE_CONFIG` | MCP 必填：配置 JSON 绝对路径 |
| `EMAIL_TRIAGE_RUN_ROOT` | 默认当前目录下 `runs`；结果为 `<run-root>/<run-id>` |
| `EMAIL_TRIAGE_BASE_URL` / `EMAIL_TRIAGE_MODEL` | 覆盖配置中的模型地址和 ID |
| `EMAIL_IMAP_HOST` / `EMAIL_IMAP_USER` | IMAP 服务器与完整账号 |
| `EMAIL_IMAP_PORT` / `EMAIL_IMAP_SSL` | 默认 993 / 1 |
| `EMAIL_IMAP_PASSWORD` | 本机进程环境中的密码，不放 Git |
| `EMAIL_IMAP_PASSWORD_FILE` | 读取本机密码文件，权限须为 0600 |
| `EMAIL_IMAP_KEYCHAIN_ITEM` | macOS 钥匙串服务名，账号使用 `EMAIL_IMAP_USER` |

## 模型与超时

真实邮件分类前，先确认服务就绪、模型已加载。首次加载可能超过配置中的单封超时，可以先用不含敏感内容的请求预热。配置可调整单封超时、总时长、调用数、输入字节数及输出 token 数。

连接、认证或超时错误会中止本轮；单封返回非 JSON 或未知类别时，只记录该封失败。带思考输出的模型如果耗尽 token 而没有分类正文，应调整输出预算或服务支持的 reasoning 设置，不要把空输出当分类结果。

## Thunderbird

1. 在 Thunderbird 中按邮箱服务商说明添加 IMAP 账号；认证方式和服务器名以你自己的账号为准。
2. 本工具用相同账号执行只读 `classify`。
3. 查看分类结果；确需目录整理时先运行 `apply` 预演。
4. 显式执行 copy 后，让 Thunderbird 同步/订阅新目录，核对数量及邮件内容。

不需要 Thunderbird 扩展，也不直接操作 profile 文件。要避免查看邮件时自动标已读，在 Thunderbird 设置中关闭“自动将消息标记为已读”；客户端自己的读信动作与本工具的只读分类是两条路径。

### 腾讯企业邮兼容性观察

2026-10-30，一次使用腾讯企业邮的校园邮箱试验中，`imap.exmail.qq.com:993` 登录成功；个人 QQ 邮箱入口不适用于该账号。这只是该账号的观察，不是所有校园邮箱的统一配置。

同次试验中：

- 自定义 keyword STORE 返回 OK，但 FETCH 未读回标签；标准系统标记可保存。
- 嵌套自建目录被拒绝，顶级目录可创建。
- modified UTF-7 中文目录可创建并在 Thunderbird 显示。

因此当前 `apply` 使用顶级目录，不依赖标签。不同账号、服务商或套餐可能有不同行为。

## `apply` 的边界

- 默认 dry-run，不写邮箱；加 `--apply` 才写。MCP 不提供此入口。
- 默认 copy：原件留在源目录；move：使用服务器支持的 UID MOVE 移走原件，没有手动删除回退。历史真实邮箱试验只执行过 copy，未验证 move。
- 使用与分类相同的配置、源目录与覆盖范围；正文截断口径必须一致，否则无法匹配结果。
- 当前采用逐封匹配；结果只覆盖匹配成功的邮件，不保证与原运行等量，检查 `matched` 计数。
- **不去重**：同一批不能盲目重复执行。遇到断线、部分失败或未知结果，先查源/目标状态，不自动重放。
- `apply.jsonl` 含主题等敏感信息，且再次执行会覆盖该文件；执行前保留需要的历史副本。
- 分类只用于建议；显式写入是用户/操作者决策，不是模型自主授权。

## 数据保留

`runs/` 保存审计、汇总、核对表与可选写入日志。不要盲目复用运行目录：再次执行可能覆盖其中的结果。`.gitignore` 只负责默认排除文件，不提供加密或访问控制。部署者需决定保存位置与权限，并了解模型服务的数据留存政策。公开分享前检查主题、理由、正文、地址、令牌等字段。
